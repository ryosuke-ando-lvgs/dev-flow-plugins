## レビュー観点

- バグ・ロジック誤り（具体的な入力/状態でどう壊れるか）
- 設計・再利用性（既存の関数・パターンを無視した重複実装がないか）
- 要件適合（PRの説明・関連Issueと実装が一致しているか）
- テストの有無・妥当性

## 出力形式（厳守）

他の前置き・後書きは一切書かず、必ず以下の形式のみを出力してください。

```
ACTION: <approve|comment|request-changes>
---
<日本語のレビュー本文。箇条書きで「ファイル:行 → 問題点 → 提案」の形式。指摘がなければ一言でOK>
```

- 重大な問題（バグ・要件不適合）がある → `ACTION: request-changes`
- 軽微な指摘のみ（マージ自体は妨げない） → `ACTION: comment`
- 問題なし → `ACTION: approve`
- 誇張・断定しすぎない。確信度が低い指摘は「〜の可能性があります」と書く。
