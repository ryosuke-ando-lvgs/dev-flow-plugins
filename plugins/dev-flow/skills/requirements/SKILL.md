# requirements（要件整理）

曖昧な依頼を、後続スキルが消費できる構造化された要件メモに変換する。

## 引数

`$ARGUMENTS` に依頼内容・Issue番号・参考リンクなどを受け取る（無ければユーザーに最初の入力を促す）。

## 手順

### Step 1: 入力の理解
依頼文・関連Issue・既存コードを読み、何が求められているか把握する。曖昧な箇所を洗い出す。

### Step 2: 要件の構造化
以下のフォーマットで整理する。埋まらない項目は「不明（要確認）」と明示する。

```markdown
# 要件: <タイトル>

## 背景 / 課題
なぜこの変更が必要か。

## ゴール
達成したい状態（測定可能なら数値で）。

## スコープ
今回やること（箇条書き）。

## 非対象 (Out of Scope)
今回やらないこと。

## 受入条件 (Acceptance Criteria)
- [ ] 条件1
- [ ] 条件2

## 制約 / 前提
技術・期日・依存など。

## 未確定事項
要確認の論点。
```

### Step 3: 不明点の確認
未確定事項が意思決定を要する場合は `AskUserQuestion` で確認し、回答を反映する。
些末な点は最も妥当な解釈で埋め、メモに「（仮定）」と注記する。

### Step 4: 保存
要件メモを scratchpad に `requirements_<短い識別子>.md` として保存し、パスを報告する。
このパスは `plan` / `orchestrate` が参照する。

## 注意事項
- 質問だけで終わらせない。妥当な解釈で埋めてから確認する。
- 受入条件は後続の `review` / `pretest` の判定基準になるので具体的に書く。
