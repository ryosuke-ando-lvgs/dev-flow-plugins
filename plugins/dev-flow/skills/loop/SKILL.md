# loop（ループ実行）

dev-flow の処理を反復実行する。タスクリストの連続消化や、CI/コメントの定期監視に使う。

## 引数
`$ARGUMENTS` に以下を受け取る:
- **対象**: `orchestrate` 全体 / 特定段階（例 ci-fix・comment-fix）/ タスクリスト
- **停止条件**: 全タスク完了 / CI green / 新規コメント無し / 最大反復回数 / 期限
- **間隔**: 定期監視の場合のウェイク間隔

## 手順

### Step 1: 反復計画の確定
対象・停止条件・間隔を確定する。曖昧なら妥当な既定で開始し、要点を確認する。
状態（残タスク・反復回数・last_seen 等）を scratchpad の `loop_<識別子>.md` に保存する。

### Step 2-A: 連続消化型（タスクリストを順に処理）
タスクリストの各項目に対し対象処理（多くは `orchestrate`）を実行する。
1件終えるごとに状態を更新し、停止条件（残0 / 上限回数）を判定する。

### Step 2-B: 定期監視型（CI/コメントを待つ）
`ScheduleWakeup` で自走させる。
- 間隔: 既定20〜30分（1200〜1800秒）。短間隔ならキャッシュ維持の都合で270秒（300秒ちょうどは避ける）。
  ハーネスが完了通知できない外部状態（CI実行等）を待つ場合のみ短間隔にする。
- prompt には「対象処理 + 停止条件 + 状態ファイルパス」を含め、毎回まとめて処理してから
  **1回だけ**再スケジュールする（複数の関心事は1promptに統合。ScheduleWakeup は次回1つしか持てない）。

### Step 3: 停止判定
停止条件を満たしたら**再スケジュールしない**＝ループ終了。結果（処理件数・最終状態）を報告する。

## ビルトイン `/loop` との違い
ビルトイン `/loop` は任意プロンプトを汎用的に繰り返す。本スキルは **dev-flow 特化**で、
段階・成果物・PR/CI/コメントの状態を scratchpad で管理し、開発フロー固有の停止条件で終了する。

## 注意事項
- 無限ループ防止のため、必ず明示的な停止条件（上限回数 or 期限）を持たせる。
- 各段階の注意事項（force push禁止・リモート判定 等）は個別スキルに従う。
- 監視を止めたいときは再スケジュールしない。
