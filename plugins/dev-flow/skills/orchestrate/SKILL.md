# orchestrate（開発フロー オーケストレーター）

dev-flow の各スキルを順番に呼び出し、開発を一気通貫で進める。**既定（auto）では承認を求めず最後まで進める。**

## 引数
`$ARGUMENTS` に最初の依頼内容（要件の種・Issue番号など）と、開始/終了段階の指定を受け取る。

## 実行順序

1. **requirements** — 要件整理 → 要件メモ作成
2. **plan** — 実装計画 → 計画メモ作成
3. **implement** — 作業ブランチ作成＋実装
4. **review** — ローカルdiffレビュー → 指摘対応
5. **pretest** — lint/test/typecheck/build を green に
6. （任意）分割コミットの整理
7. **pr-create** — push → PR作成
8. **pr-review** — PR上に観点コメント投稿（レビュー投稿する場合）
9. **ci-fix** / **comment-fix** — CI失敗・新規コメントに対応

## 進め方

- 各段階は対応するスキルの手順に従って実行する。
- 段階間のデータ（要件メモ・計画メモ・ブランチ名・PR番号）は scratchpad と git 状態で受け渡す。
- 引数で開始段階が指定されていればそこから、終了段階が指定されていればそこまで実行する。

### 承認モード（引数で選択。既定は auto）

**既定は承認を求めず最後まで進める。** 確認が必要なときだけ `AskUserQuestion` を使う。

- **`auto`（既定）**: 各段階で承認を求めず一気通貫で走る。
  - **requirements の完了までは確認不要**。要件整理は妥当な解釈で進め、結果は後続に渡すだけ。
  - 以降も基本は自動。**確認するのは次の2つだけ**:
    - 判断が割れて勝手に進めると手戻りが大きい致命的分岐（例: 破壊的変更・データ移行の要否）
    - 取り消しにくい外向きアクションの直前（push / PR 作成）※プロジェクト規約で自動可なら省略
- **`gates`**: 重要ゲート（計画提示後・PR作成前）のみ確認する。
- **`each`**: 全段階の境目で確認する（じっくり伴走したいとき）。

引数例: `/dev-flow:orchestrate <依頼>`（=auto）/ `... --mode=each` / `... --mode=gates`。
「全自動で」「お任せ」→ auto、「ゲートだけ」→ gates、「一段階ずつ」→ each と解釈する。

## 状態管理

進捗を scratchpad の `flow_<識別子>.md` に記録する（現在段階・成果物パス・ブランチ・PR番号）。
中断後の再開や `loop` からの呼び出しで参照する。

## 注意事項
- 各段階の「注意事項」（force push禁止・リモート判定・直接コミット禁止 等）は個別スキルに従う。
- 既定は auto（承認を求めず進める）。確認を増やしたいときだけ `--mode=gates/each`。
- 失敗した段階は止めて正直に報告し、次へ進めるかを確認する（auto でもエラー時は確認する）。
