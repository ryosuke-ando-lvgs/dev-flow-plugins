# plan（開発計画）

要件メモを入力に、実装計画を作成する。

## 引数

`$ARGUMENTS` に要件メモのパス、または計画したい内容を受け取る。
`requirements` 直後なら scratchpad の `requirements_*.md` を自動で探して使う。

## 手順

### Step 1: 要件と既存コードの把握
要件メモを読む。関連コードの構造・既存の再利用可能な関数/ユーティリティ/パターンを調べる。
探索範囲が広い場合は `Explore` サブエージェントを並列で使う。新規実装より既存活用を優先する。

### Step 2: 方針の検討
複雑な場合は `Plan` サブエージェントで実装方針を設計させ、トレードオフを検討する。

### Step 3: 計画メモの作成
以下を scratchpad に `plan_<識別子>.md` として保存する。

```markdown
# 実装計画: <タイトル>

## 方針
採用するアプローチと理由（代替案は採用理由に必要な範囲のみ）。

## 変更対象ファイル
- path/to/file — 何を変えるか
- 再利用する既存関数: path:行 — 用途

## タスク分解
1. [ ] タスク1
2. [ ] タスク2

## 影響範囲 / リスク
副作用・後方互換・要注意点。

## 検証方法
実行手順・テスト観点（受入条件と対応づける）。
```

### Step 4: 確認
計画の要点を簡潔に提示し、判断が要る分岐は `AskUserQuestion` で確認する。

## 注意事項
- 既存実装の再利用を最優先。重複コードの新規追加を避ける。
- 計画は scan しやすく、かつ実行可能な粒度に保つ。
- 検証方法は受入条件と対応づける。
