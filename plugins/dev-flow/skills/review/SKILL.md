# review（ローカルdiffレビュー）

push前の変更diffを観点別にレビューし、必要な修正を行う。

## 引数

`$ARGUMENTS` にレビュー対象（ブランチ名・コミット範囲）や重点観点を受け取る。無指定なら
ベースブランチとの差分全体を対象にする。

## 手順

### Step 1: 差分の取得
```bash
git remote -v
git fetch origin
git diff origin/develop...HEAD   # develop が無ければ origin/main
git diff                          # 未コミット分があれば併せて確認
```

### Step 2: 観点別レビュー
以下の観点で確認し、指摘を `ファイル:行` 付きで列挙する。

- **正しさ / バグ**: エッジケース、null/境界、非同期、例外、リグレッション。
- **要件適合**: 要件メモの受入条件を満たすか。スコープ外の混入が無いか。
- **設計 / 再利用**: 既存関数で置換できる重複、過剰な複雑さ、命名。
- **セキュリティ**: 入力検証、機密情報の露出、権限。
- **テスト**: 変更に対するテストの有無・妥当性。

### Step 3: 修正
指摘のうち軽微・明確なものは修正する。判断が分かれるものは
要点を提示し合意を得てから直す。修正は追加コミットで積む。

### Step 4: 報告
指摘一覧（対応済み / 要判断 / 見送り理由）を簡潔にまとめて報告する。

## 注意事項
- 指摘は重要度順に。確証の低い推測は「要確認」と明示する。
- 大規模変更や別観点が欲しい場合は `code-review` サブエージェントを併用してよい。
- ここでは lint/test の実行は行わない（`pretest` の担当）。
